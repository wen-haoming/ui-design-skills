# 浅色 AI 工作流编辑器

## 目标与适用场景
为自动化、AI Agent、审批及集成编排产品设计节点式工作流编辑器。让用户同时理解流程如何运行、当前节点如何配置、修改是否已生效。优先业务可读性和状态可信度，不以装饰制造复杂感。

## 先确认输入
从用户已有需求确定业务流程、目标用户、主要设备、交付格式和技术约束；只有缺失信息会实质改变结果时才提问。没有真实数据时，明确标注示例数据。不要把参考图片中的品牌、业务量和准确率当成用户的真实数据。

## 视觉规则
- 用白色、近白和浅灰建立面板层级，深色文字承载主信息，细灰边框与轻阴影分区。
- 蓝色集中表达主操作、选中节点、可编辑控件和 AI 变更提案；避免全屏滥用强调色。
- 条件分支可用绿色、粉红等区分，但必须配合 Yes/No 或业务条件文字，不能只靠颜色。
- 使用紧凑无衬线文字、统一细线图标、小圆角卡片；业务名称优先，技术类型退为辅助标签。不用 emoji 充当图标。
- 用留白、对齐和一致间距建立秩序，不给每张卡堆厚阴影与大圆角。

## 布局骨架
1. 最左为全局导航，按工作区、运营、管理分组。
2. 顶部为面包屑与全局辅助区；其下放流程名、草稿版本、保存状态、历史、测试和发布。
3. 左侧步骤库支持搜索，按触发器、AI、逻辑、动作、人工处理分类。
4. 中央为连线画布，主要流程从上到下，条件节点左右分支后汇合；不要为贴合参考强行改变业务拓扑。
5. 右侧为当前节点配置面板，按配置、字段、测试分区，按业务需要展示模型、提示词、输出字段和阈值。
6. 画布底部放缩放工具和自然语言修改入口，不挤占主流程。

## 核心组件与状态
- 节点卡：统一服务图标、类型标签、业务标题、配置摘要；运行指标仅在有数据时显示。
- 选中节点：蓝色描边，与右侧配置同步；切换节点时保留或明确处理未保存输入。
- 条件分支：显示判断、分支标签和去向，连线尽量正交，避免交叉和穿卡片。
- 插入步骤：上下文搜索浮层，展示服务分组、动作解释及建议步骤；支持取消与键盘选择。
- AI 修改提案：新增或改变的节点以虚线蓝框等差异样式突出，弱化未修改部分；说明修改内容与数量，提供丢弃和应用。应用只修改草稿，不自动发布。
- 发布确认：展示变更清单、校验结果、警告、发布说明和影响；立即发布或灰度选项只在实际支持时提供。

## 执行步骤
1. 先定义真实业务链路，例如触发 → AI 提取 → 条件判断 → 自动动作或人工复核 → 汇总。
2. 若交付可运行代码，先设计节点、边、分支、配置、草稿、发布版本、运行状态和 AI 提案的数据结构；遵守当前环境的代码工作规范。
3. 先完成页面骨架和一条可理解的完整流程，再细化节点与配置面板，避免只画漂亮卡片。
4. 用统一组件覆盖默认、悬停、聚焦、选中、插入、AI 提案、发布确认状态。
5. 将 AI 修改明确拆成生成提案、审阅差异、应用草稿、单独发布，不能悄悄改线上流程。
6. 补充加载、空状态、失败、无权限、未保存、校验失败与窄屏策略，并标明这些是产品扩展设计，不是参考图已经证明的功能。
7. 按用户要求交付设计或实现，说明已完成状态及尚未实现的行为。静态稿不能声称已验证拖拽、动画或真实执行。

## 建议设计 token（复现起点，不是原作测量值）
- 4/8px 间距网格；主体字号可从 13–14px 起，根据清晰度调整，不为紧凑牺牲可读性。
- 全局导航约 176–208px，步骤库约 176–224px，右侧配置约 280–340px；根据内容和视口调整，不固定硬套。
- 控件圆角约 6–10px，边框约 1px；保证文字与状态的对比度。
- 画布实现可考虑平移缩放，小屏把步骤库和配置面板改为抽屉，而非等比缩小全部内容。

## 可选实现方案
设计稿可用 Figma；Web 实现可考虑 React 与 React Flow 等节点画布方案，样式沿用项目现有体系。上述均为复现建议，不能宣称参考原作使用了这些工具，不能仅凭外观认定为 shadcn/ui、Tailwind 或任何组件库。

## 质量检查
- 一眼找到入口、选中节点、条件分支和发布操作。
- 草稿、保存状态、已应用提案与线上版本明确区分。
- 节点与配置面板同步，切换不误覆盖；应用和丢弃提案效果清楚。
- 连线不穿卡片，浮层不遮关键项，长标题、错误提示与空字段不会破坏布局。
- 状态不只靠颜色；键盘焦点、可点击区域、对比度及缩放后的可读性合格。
- 发布前展示影响与校验；错误有具体原因和恢复路径。
- 需要实现但尚未验证的交互如实标记，不把静态图当可运行证据。

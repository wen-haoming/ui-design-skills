# 重点用法：18条增量精读

这些均为调用建议，不是上游运行结果。未提供实施项目，未核对目标项目installed versions；每次实际使用先读package.json、lockfile、包内文档与CLI --help，不盲目升级。**14条全文SKILL.md + 4条定向章节；全文不等于全部references。**

## 最先用这8个（按场景择一，不是全装）
1. building-components：组件API/受控状态/可访问性，比再造视觉风格入口更实用。
2. json-render/vue：需要生成式表单时选Vue，不强塞React；core只作为catalog按需补充，普通静态页面不用。
3. streamdown：仅React流式中文内容用，先修正旧SDK例子与域名边界。
4. chat-sdk：跨平台机器人，而非网页聊天UI。
5. queues：单次后台扇出、流量缓冲与消费者幂等。
6. workflow：确有持久多步、长等待或审批时才选，不与queues默认叠装。
7. cdn-caching：Vercel站点旧内容/成本排障先分清缓存层。
8. vercel-tracing：慢服务端请求才用，前端LCP仍需浏览器证据。

Vue/VitePress/小程序：优先组件原则，按真实服务端需要选缓存/队列/工作流；没有查到微信小程序专用第一方技能。不为“收集得多”全装。

## building-components
- 适用：设计系统中的可访问组件/API；React参考的工程原则也可迁移Vue
- 不适用：不是视觉灵感检索；不能把React hook/as-child原样贴到Vue、小程序
- 前置与版本：先核对框架、组件primitive及TypeScript版本；上游未列统一最低版本；本轮未检查项目installed version
- 输入：组件职责、交互状态、父级控制方式、键盘契约、现有token与primitive

**中文调用例（仅建议）**
> 用 building-components 设计一个可受控/非受控的筛选弹窗。先读 accessibility/state 对应参考，给API与键盘契约；沿用项目框架，不安装依赖、不发布组件。

**核心规则**
- 先选语义元素，再做ARIA增强；区分props/slots组合与继承。
- 受控模式父级是单一真源；非受控模式只读default值初始化，不制造两份互相同步的状态。
- 在打开、关闭、卸载和内容变化时定义焦点去向；恢复到触发器，不能只测试视觉出现。
- 上游focus trap代码是教学片段，未覆盖所有动态/禁用元素；不要复制全局outline:none或自制陷阱当成已合规，优先成熟primitive并测试。

**期望输出**：API草图、状态转移表、slot边界、键盘/焦点与主题检查表

**可观察验收**
- Tab/Shift+Tab可用，Escape关闭，焦点回到正确触发器；读屏名称存在。
- 父级改value会立即反映；defaultValue不抢受控状态；中文长文、200%缩放和明暗主题不溢出。
- 自动化无障碍检查只补充真实键盘/读屏验证，不声称WCAG认证。

**路由**：primary building-components；视觉研究仍走已有refero-design，审成品时再补web-design-guidelines
**来源**：[vercel/components.build / skills/building-components](https://github.com/vercel/components.build/blob/0861fbcfe4f78c50eaafc202f5fb7661d641ddff/skills/building-components/SKILL.md)；commit `0861fbcfe4f78c50eaafc202f5fb7661d641ddff`；许可 Apache-2.0。
**阅读深度**：SKILL.md全文；未读全部references/AGENTS.md；额外参考：references/principles.mdx（全文）；references/state.mdx（全文）；references/accessibility.mdx（语义/键盘/读屏/视觉；焦点管理与恢复两段，非全文）。

## json-render/core
- 适用：AI产出受约束的声明式UI规格/表单/仪表盘；先定schema与catalog
- 不适用：不是任意代码生成器；不保证内容审美、语义完整或业务授权
- 前置与版本：核对@json-render/*同版本；experimental_composeSpec自v0.21.0起且随时可能变更，默认不启用实验路线；核对zod与实际renderer schema
- 输入：允许的组件、props schema、动作白名单、初始状态、最大节点/深度、错误回退要求

**中文调用例（仅建议）**
> 用 json-render 的 core 帮我把生成式表单限定在 Card/Text/Input/Button 四类。先给catalog与合法/越权反例，所有提交仍由服务端授权，不调用模型。

**核心规则**
- Schema定结构、Catalog定组件与动作能力、Spec是数据；三者不可混为可信代码。
- 用validateSpec检查引用与条件；autoFixSpec区分lossless/lossy，丢子节点不应静默变成“成功”。
- 流式JSONL patch不是每个chunk都可直接JSON.parse；保留最后有效快照与取消状态。
- 结构校验不等于权限校验；客户端visibility和action名称不能授予服务端写权限。

**期望输出**：有限catalog、示例spec、校验/重试/回退策略、动作权限表

**可观察验收**
- 未知组件、悬空引用、循环/超深树被拒；默认值和schema转换另有测试。
- 即使生成了“删除”按钮，未批准的动作也不能执行；有损修复显示缺项而非伪装完整。

**路由**：primary 仓库限定的 json-render/core（frontmatter是core，避免与其它core撞名）；Vue渲染再补vue

## json-render/vue
- 适用：Vue3/Vite里的JSON驱动表单和交互UI，最贴合本用户的非React增量
- 不适用：不是微信小程序renderer；也不是让普通VitePress文章接入整套生成UI的理由
- 前置与版本：正文peer要求Vue ^3.5.0、Zod ^4.0.0；@json-render/vue/core要版本匹配。先核对项目实际安装版本，不擅自升级
- 输入：已有Vue组件、catalog、state路径、事件到动作的映射、Pinia/外部store接口

**中文调用例（仅建议）**
> 用 json-render 的 vue 技能把一个只读订单卡片和可编辑筛选表单接到现有Vue3项目。列出slot、ref和双向绑定契约；先给草图与fixture，不装包。

**核心规则**
- defineRegistry映射到可信Vue组件，children对应默认slot，顶层slots只放具名slot。
- 状态路径用JSON Pointer；$state是读、$bindState放在自然value/checked属性以写回，别发明statePath prop。
- useStateStore().state是ShallowRef，要读state.value；外部StateStore可接Pinia但需核订阅/快照行为。
- 组件emit事件，经ActionProvider受控派发；不能从模型文本直接构造执行函数。

**期望输出**：Vue registry草图、provider树、状态/slot映射表、无模型fixture

**可观察验收**
- 修改输入只更新指定路径；默认slot/具名slot都呈现且不重复。
- 取消流式响应保留上次有效spec；非法action被服务端拒绝；Vue类型检查与交互E2E另跑。

**路由**：primary json-render/vue（frontmatter vue，不是泛Vue最佳实践）；需要catalog时按需读core

## ai-elements

- 输入：现有聊天协议、message parts、工具生命周期、主题和组件目录归属

**中文调用例（仅建议）**

**核心规则**

- 消息按parts分型处理；文本、工具调用/结果及失败状态不可一律当字符串。
- 工具授权由业务服务端与明确审批决定，按钮显示“已批准”并不构成实际授权。
- 上游Node18、主题data-theme等描述需与项目当前实现核对；不把这些当所有shadcn项目的统一事实。

**期望输出**：最少组件清单、状态映射、可访问输入/结果区与文件改动计划

## streamdown
- 适用：React流式Markdown、中文/公式/代码/图表呈现，兼顾内容创作

**中文调用例（仅建议）**
> 用 streamdown 检查中文流式文章：分块代码围栏、粗体、公式和外链。先读security参考，列严格域名规则和Tailwind扫描项，保留链接确认，不接真实模型。

**核心规则**
- 流式中isAnimating与caret配合；静态文章明确mode=static，不把每次重绘误作流。
- Tailwind4的@source与v3 content不同；只加已装插件的扫描路径；公式还需KaTeX CSS。
- security参考比简介更谨慎：协议/前缀默认宽松，Link Safety弹窗不是清洗器。自定义rehype链需重建sanitize/harden。

## chat-sdk
- 适用：服务端跨Slack/Teams/Discord等平台机器人；含Nuxt/Hono等模板线索
- 不适用：不是网页聊天useChat组件；不要为单平台成熟集成无故迁移；不承诺每个适配器都同能力
- 前置与版本：chat及所选@chat-adapter/*实际版本；读node_modules/chat/docs与resources；适配器需区分官方/厂商/社区，按catalog核对流式/模态/锁支持
- 输入：目标平台、事件类型、bot或user身份、订阅/去重、部署框架、审批要求

**中文调用例（仅建议）**

**核心规则**
- 入口区分提及、订阅消息、交互回调；thread状态和分布式锁不是内存变量能替代的。
- 适配器catalog替代已deprecated的chat/adapters发现入口，不能根据平台名字猜包和权限。
- 跨平台统一抽象不代表流式和cards行为完全相同；先查getFeatureSupport。

## workflow
- 适用：审批/长等待/重试/跨请求持久的多步任务；支持多框架集成
- 不适用：短同步请求或单次后台任务不要强加workflow；不是用户已授权发布内容
- 前置与版本：核对installed workflow主版本与bundled docs；本正文涵盖Workflow5。@workflow/vitest与workflow须同主版本；框架接入按实际Nuxt/Vite/Next读取
- 输入：状态机、外部副作用、幂等键、审批人、超时、重试分类、事件规模

**中文调用例（仅建议）**
> 用 workflow 审阅“生成草稿→等待我批准→导出文件”的状态机。只设计，列step边界、批准身份校验、超时/拒绝/重复回调反例；不启动真实run。

**核心规则**
- workflow函数只编排；网络/Node模块与副作用放step，等待用durable sleep/hooks而非setTimeout。
- step结果持久化不等于外部副作用恰好一次；处理“远端成功、checkpoint失败”要幂等/事务。
- 创建hook的token不是授权本身：resume入口验签、核对session审批人和任务版本、拒绝过期和重放。
- 批量并发有界；子run界定失败/历史，不自动降低扇出；Promise.all只用于独立工作，allSettled要检查每个失败。
- 测试分step单测与@workflow/vitest集成；不可把vi.mock能拦截所有VM代码作为前提。

**期望输出**：可重放状态机、step/编排表、重试与批准边界、测试矩阵

**可观察验收**
- 拒绝/超时终止；错误主体或旧版本批准无效；回调重放只产生一次逻辑结果。
- 模拟步骤崩溃后恢复不重发不可重复写入；有计划验证持久化恢复而非只单测函数。

**路由**：primary workflow；单次扇出用queues，不重复安装其上游同名镜像

## queues
- 适用：异步任务缓冲、消息扇出与独立consumer group；Nuxt/Nitro同样可用
- 不适用：不是构建队列排队故障；多步审批别手写一串topic代替workflow
- 前置与版本：正文标public beta；核对@vercel/queue或Python vercel-queue版本、项目授权、函数trigger schema。最低数字未固定，实施前以installed docs为准
- 输入：topic/payload schema、消费组、业务幂等范围、留存/延迟、毒消息处理和可观测指标

**中文调用例（仅建议）**
> 用 queues 设计“文章保存后生成两个独立格式”的后台任务。假设重复投递，给业务幂等键、重试/毒消息表和Nuxt接入检查；不发布消息。

**核心规则**
- at-least-once是投递语义，不是exactly-once业务效果；生产者idempotencyKey窗口有限，消费者也要幂等。
- handleCallback返回即确认、抛错重试；注册experimentalTriggers才会有push投递。
- 毒消息不能静默ack当成功：先留失败记录/告警与恢复策略，再达到阈值确认终止。
